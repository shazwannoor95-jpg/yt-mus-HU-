# YTM Head Unit 0.4.9 — Japanese readings and lyric layers

Kuromoji/IPADIC was already installed in 0.4.8. It emits separate tokens for the parts of forms such as `あっ + て` and `握りしめ + て + た`. Converting each token alone kept the small tsu verbatim and inserted a space at every boundary. The renderer now combines inflections, auxiliary forms, connective particles and suffixes before applying Hepburn. It handles the irregular Japanese person counters and uses contextual particle readings `wa`, `e` and `o`. Long-vowel marks in dictionary pronunciation become macrons, as in `gakkō`. Separate kana and inflection vowels remain, as in `omou`. Kana across a track can establish Japanese context for Han-only lines. Mixed text keeps its Latin words, numerals and punctuation.

The optional 12.8 MiB IPADIC download still needs 14 MiB free. It stays outside the APK and loads lazily. A 64 MiB host JVM measured 38.2 MiB heap growth after dictionary initialization and 33.1 MiB retained during the active batch. The four reference lines took about 0.52 seconds including dictionary loading on that host. Android PSS and head-unit latency need device measurements. Under memory pressure, kana fallback remains available and unknown kanji stay in the original script. The same dictionary and dependencies work across profiles. Kuromoji (Apache-2.0) already exposes the morphology needed here. Kuroshiro and lyric-romanizer use JavaScript plus a tokenizer. BiangBiang Kana is a larger mobile app under Elastic License 2.0. No upstream code from those three projects was incorporated. [Kuromoji](https://github.com/atilika/kuromoji) · [Kuroshiro](https://github.com/hexenq/kuroshiro) · [lyric-romanizer](https://github.com/thedavidweng/lyric-romanizer) · [BiangBiang Kana](https://github.com/veeso/BiangBiang-Kana)

The provider order is supplied translations, Unison, and optional Google Cloud Translation Basic v2. The last option requires a user-managed API key for an enabled billed project. It sends only the original lines that still need translation and stores the key encrypted in separate lyric settings through Android Keystore. It does not use any account cookies or tokens. Translation keeps timestamps and groups with the original lines. The UI labels machine results by provider and separates translation from reading diagnostics. Optional Cloud Translation does not use on-device models. Both service endpoints were blocked by the workspace proxy, so Malay and English rendering were verified with fixtures and live translation remains unverified. Indonesian and the existing target options remain available.

ML Kit 17.0.3 exposes Malay, Indonesian, English and Japanese and publishes both ARM32 and ARM64 libraries. Its AAR alone is 27.7 MB and contains an 11.6 MB uncompressed ARM32 translator library. Its dependency graph introduces Play Services and Firebase, and its on-device models require additional per-language downloads. To preserve the existing dependency graph and low-memory footprint, this release does not install ML Kit or its models. ## Authentication protection

- Baseline commit `09c3cb6c36ec801f7d18cab58724b5f5d412f91b`. The only pre-existing working-tree item was the untracked audit Markdown.
- Protected code changes: **NONE**. GoogleSignIn, WebSession, MusicApi, account tests and account settings were compared against the baseline. MainActivity changed only to dispatch lyrics settings. The manifest and Gradle configuration changed only for version metadata.
- Application ID remains `my.ytmhu`. The signed APK uses the same debug certificate as 0.4.8.
- Live account session persistence: **not verified** on a physical head unit. The permanent lock is recorded in [AGENTS.md](../AGENTS.md).

## Verification and artifact

Gradle passed 40 tests with zero failures or skips. The unchanged AccountVerification (7), GoogleSignIn (2), legacy WebView advice, and Android31 (9) regression cases all passed. Lyrics fixtures cover the Shamrock examples, other scripts, missing or malformed provider output, low memory, language and track changes, timestamp preservation, three text layers, and the existing playback controls. The landscape image was rendered by Robolectric from fixture data. It is not a head-unit capture or evidence of a live translation response.

The debug APK is 1,247,134 bytes (+6,356 bytes from 0.4.8). API 27 remains the minimum. The APK contains DEX with no ABI-specific libraries. REA and Craft Anything inspected the upstream installer and compared Android packages. The Android archive retained all existing assets and changed the app DEX and versioned manifest.
